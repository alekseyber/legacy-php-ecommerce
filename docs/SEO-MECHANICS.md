# Механика трафика: фасеты, UTM-лендинги, городские страницы

Три вещи, которые в самописном магазине обычно делают отдельными костылями, здесь были частью движка: фильтр с фасетами на битовых масках, подмена заголовка и анонса под рекламное объявление, страницы городов с автоподстановкой названия в падежах.

Разбор для тех, кому интересно, как это устроено внутри, и с честным перечислением ограничений.

## 1. Фасетный фильтр на битовых масках

`app/widgets/filter/Filter.php` — 1 559 строк, 24 метода.

Идея: значение атрибута имеет номер бита (`sdvig`), у товара в `attribute_product` лежит целое `bitmask`, где нужные биты выставлены. Тогда:

- «есть ли у товара значение» — побитовая проверка, без JOIN'а по таблице значений;
- «сколько товаров с таким значением» — одна агрегатная функция по выборке:

```php
$sql_part = 'SELECT attrgr_id, alias, BIT_OR(bitmask) AS bitmask FROM attribute_product ...';
// дальше decbin() и сравнение позиций — какие биты выставлены хотя бы у одного товара
```

Фасеты считаются по той же выборке, что и товары, поэтому фильтр не делает N запросов на N групп.

Что ещё внутри:

- **Разделение атрибутов на «табличные» и «нетабличные»** (`tablegrupp`, `tablenobinary`): одинаковый движок обслуживает простые признаки и справочники со своими таблицами;
- **кэш с ключом по параметрам** (число колонок, авто-раскладка, шаблон) — `Cache::instance()` и метки;
- **несколько выходов**: `getHtml` (разметка), `getPriceJs` (слайдер цены), `getFilterLink` (сборка URL), `getTagsHtml` (SEO-теги), `getFilterYml` (выгрузка для маркетплейса).

**Ограничения, которые надо знать:**

- 62 значения на группу максимум: больше бит в знаковом целом не влезает;
- читаемость низкая: `decbin`/`iconv_strlen` без комментариев понятны только автору;
- изменение состава атрибутов требует пересчёта масок;
- рядом в репозитории лежат четыре копии этого виджета (`Filter_old*`, `Filter_no_nocolorgr`) — след работы без git.

## 2. Подмена H1 и анонса под рекламное объявление

Таблица `utm`: `key_item` (числовой код кампании), `title` (H1), `promo` (анонс), `description`, `all_on`, `status`.

В контроллере категории:

```php
$utm_content = $_GET['utm_content'] ?? 0;
if ($utm_content) {
    $utm_content = preg_replace('#[^\d]+?#', '', $utm_content);   // оставляем только цифры
    $utm = R::getRow('SELECT id, key_item, title, promo FROM utm WHERE key_item = ? AND status = 1', [$utm_content]);
    if ($utm) { $_SESSION['utm_id'] = $utm['id']; }
}
...
if ($utm['title']) { $contData['htitle'] = $utm['title']; }   // подмена H1
if ($utm['promo']) { $contData['promo']  = $utm['promo']; }   // подмена анонса
```

Два следствия, которые важны:

1. **Маркетолог работает без разработчика**: в админке есть раздел UTM с формой и действием «копировать объявление» (`app/controllers/admin/UtmController.php`).
2. **Заказ помнит объявление**: `utm_id` сохраняется в сессии и уходит в заказ — атрибуция заложена с самого начала, а не приделана потом.

Проверка: открыть страницу категории с `?utm_content=123`, где `key_item = 123` активен, — заголовок и анонс заменятся.

## 3. Городские страницы с падежами

Таблица `citypage` хранит на каждый город:

- `alias`, `seolink` — адрес;
- **пять словоформ названия**: `city_name`, `city_bname`, `city_cname`, `city_dname`, `city_iname`;
- `title`, `promo`, `content`, `meta_title`, `meta_description`, `content_on`;
- `city_id` — привязка к городу доставки.

Пять форм нужны, чтобы текст выглядел написанным под город, а не подставленным: «Угги **в Москве**», «доставка **по Москве**», «**Москва** и область» — без конструкций вида «доставка по Москва». Общие блоки (шапка, низ, заголовок блока доставки) живут отдельно в `citysettings` с флагом `selected` — правятся один раз для всех городов.

`CitypageController::viewAction` собирает страницу: мета-теги из записи, при отсутствии — подстановка из параметров города, дальше общие блоки и данные доставки.

**Ограничения:** пять колонок захардкожены под русский язык (для другого языка — переделывать), город заводится вручную, автоматического определения города для подстановки нет — только выбор города доставки.

## Почему это стоит показывать

Это решения человека, который думал не только о коде: фасеты — про конверсию, UTM-лендинги — про рекламные кампании, города — про локальный поиск. Обычно такие вещи появляются «после запуска, когда прижало»; здесь они были в движке.

Для найма это второй аргумент (первый — актуальный стек), но он редкий: разработчик, который понимает, зачем бизнесу H1 на странице выдачи.
