# Демо-стенд: как поднимался и что проверено

Стенд собран из полной выгрузки с хостинга (13.07.2023) и дампа БД того же дня. Задача была не «посмотреть код», а убедиться, что магазин действительно работает: каталог, корзина, заказ, письмо, админка.

## Состав стенда

```
docker compose up -d     # web (php:7.0-apache) + db (mysql:5.7) + mail (mailpit)
docker compose stop      # погасить
```

- `web` — `php:7.0-apache`, доcroot `public/`, `AllowOverride All`, расширения `pdo_mysql`, `mbstring`;
- `db` — `mysql:5.7`, дамп импортируется при первом старте (51 таблица, 161 товар, 18 категорий);
- `mail` — `axllent/mailpit`, локальный SMTP-приёмник: письма магазина не уходят наружу, а складываются в веб-интерфейс.

## Что пришлось поправить относительно «как лежало на хостинге»

1. **PHP 5.6 не годится**: код использует оператор `??` в 76 файлах — на 5.6 это `Parse error`. Рабочая версия — 7.0.
2. **`.htaccess` с прода** редиректит на https (`301` на `https://…:8090`), для локального стенда взят упрощённый вариант с rewrite в `public/`.
3. **`config_db.php`**: хост БД — имя сервиса `db`, а не `localhost`.
4. **права**: `tmp/`, `public/upload`, `public/images` должны быть доступны на запись www-data — иначе лог ошибок молчит, а загрузка картинок падает.
5. **локальный SMTP**: в конфиге `smtp_login` должен быть валидным адресом (используется в `setFrom`), иначе SwiftMailer падает с «Address in mailbox given [] does not comply with RFC 2822».

## Проверено (не «должно работать», а прогнано)

- главная — 200, 225 КБ, слайдер и фотокаталог;
- категория `/men` — 200; карточка `/women/classic/classic-mini-ii-polusapogi` — 200, цена и цвета подтягиваются из БД;
- корзина: товар добавился с размером и цветом, пересчёт суммы, расчёт доставки для Москвы (бесплатно от 5000 ₽);
- **заказ оформлен целиком**: запись в `orders` (номер `1225-10`, сумма 8800 RUB, адрес, телефон), страница `/cart/orderdone` с номером заказа, письмо «Сделан заказ №1225-10» на `orders@…` перехвачено локальным SMTP;
- админка `/satis`: вход (пароль тестовый, ставился в БД), дашборд — 115 новых заказов, 161 товар, 11 новостей, 18 категорий, 7 страниц, 8 групп фильтров; список заказов с фильтрами по телефону, номеру, статусу и дате доставки.

Скриншоты: `docs/screens/01-main.png`, `02-checkout.png`, `03-order-done.png`, `04-admin.png`.

## Что осталось непройденным

- загрузка/ресайз картинок из админки — в образе нет `gd` (репозитории Debian stretch архивные, собрать расширение нечем); на хостинге с нормальным PHP это решается `apt install libpng-dev && docker-php-ext-install gd`;
- реальные интеграции: СДЭК (расчёт идёт, потому что данные зашиты в параметры заказа), платёжные системы, Яндекс.Маркета выгрузка;
- почта на настоящий SMTP — проверялась на локальном приёмнике, отправку наружу намеренно не настраивали.

## Данные

В дампе, из которого собран стенд, есть реальные заказы 2022–2023 годов: имена, телефоны, адреса. Для публичных материалов они не годятся: скриншот списка заказов в репозиторий не положен, в документации цифры агрегированные.
